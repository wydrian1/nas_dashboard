# Release 1.1.0 — deadlines, versions and Android updates

- The sidebar shows the web version, including on narrow screens; the native toolbar/menu shows the installed Android version. Web/package and APK versions are 1.1.0; Android versionCode is 7.
- Tasks now have an immutable creator and an optional real calendar deadline (2000–2099). Existing task IDs, text, completion and timestamps remain unchanged. Legacy tasks belong to the configured owner; no date means no reminder. Only the creator can list/change/delete their tasks. Notes remain shared among admins as before; Pokémon readers gain no task access.
- An independent worker timer checks every 10 seconds, including during awaited shop scans/FCM calls. Starting at 10:00 Europe/Budapest (DST-aware), one transactional run per local day queues creator-only reminders for two/one days before and every overdue day while unfinished. The due day itself is not a requested threshold. After downtime, only the current day is checked, not missed past days. New/edited tasks after that day's check participate next day.
- Only active, unrevoked, push-enabled creator devices with valid tokens/leases receive reminders. Task edits/completion/deletion cancel pending reminders. Immediately before FCM dispatch, current ownership, completion, date, day, user role and device authorization are checked again, including after OAuth awaits. An already accepted/in-flight FCM message cannot be recalled. Existing at-most-once/uncertain-send and expiry behavior is preserved.
- Authenticated `/api/mobile/update` serves metadata derived from the *published APK bytes*; `?apk=1` serves those same bytes. Anonymous, revoked, expired or inactive devices are denied. No browser-cookie fallback, external download URL or redirect is accepted. The app checks on foreground/manual request and approximately every six hours via Android WorkManager (subject to OS scheduling); it automatically downloads to private cache, then checks size, SHA-256, package, exact version and the existing signer. Failure never starts installation.
- When foregrounded, the app starts the system installer once per newer version. In the background it posts an installation notification. Android may require the per-app unknown-source permission and confirmation; this is **not silent device-management installation**. Cancelled installation can be retried from the app menu. The existing 1.0.5 app needs one initial manual installation of 1.1.0 to obtain the updater.
- `Request-Deployment.mjs` authenticates the broker's terminal result and matches its release ID/commit before queuing an admin-only success notification. The version comes from that exact committed package, not the caller's current source. Failure/rollback/uncertain jobs do not announce success; replaying the announcement for an ID is idempotent. Delivery still depends on active registered devices, Android permissions and FCM availability. GitHub PR merge is separate from deployment.

Verification: full Node tests/typecheck/staging build; isolated production HTTP checks using synthetic users/devices/tasks; signed Android build, unit tests/lint; pre/post-deploy protected data/private-file hashes, SQLite integrity/FKs and live role/version/APK checks. Physical-phone installation and receipt require a phone-side check.
